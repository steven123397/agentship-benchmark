# 隐藏故障与边界场景协议

本协议固定场景、可观察结果和证据要求。协调方可以使用候选已经提供的运行入口、测试接缝和资源名称构造故障，但不得要求 spec 未规定的内部结构。只靠 Agent 自述或静态代码不能把场景记为通过。

## 共同前置条件

- 候选工作树 `HEAD` 等于冻结结果 commit，且开始前干净。
- 使用独立 Compose 项目名、宿主端口、网络和数据卷；记录实际版本与环境变量。
- 固定数据校验通过，`/health` 与 `/ready` 返回预期 envelope。
- 每个场景记录构造方式、时间线、公开 API 观察、必要的候选测试输出、资源清理结果和未验证项。

## S1：双 Worker 与有效所有权容量

启动 2 个 Worker，提交至少 6 个足以重叠执行的合法查询。通过候选提供的运行事实或集成观察接缝证明任一时刻有效执行所有权不超过 4，并证明两个 Worker 都实际取得过所有权。仅统计 `running` 状态数量不足以证明本场景，因为失租但尚未物理停止的执行活动不属于有效所有权。

## S2：失联接管与 generation fencing

让一个 Worker 在执行中失联，保留平台与 analytics 数据，再由另一个 Worker 接管。运行在接管期间不得回退到 `queued`，执行尝试递增且最终收敛。恢复旧执行者或重放旧发布路径后，旧 generation 不得改变当前状态、结果或审计事实。

## S3：自动尝试分类与上限

分别构造租约丢失或 `analytics_unavailable`，以及 `query_timeout`、查询语义错误和内部错误。前一类可以自动形成新执行尝试，后一类直接失败；任何运行最多 3 次执行尝试。自动尝试不得覆盖已经持久化的取消意图。

## S4：取消收敛与终态竞态

覆盖 queued 取消、running 取消、重复取消、取消请求与成功发布的两种先后顺序，以及 `cancelling` 时所有者失联。取消先持久化时不得发布结果或领取新尝试；成功快照先原子发布时，迟到取消保持 `succeeded`。每条路径最终离开 `cancelling`。

## S5：结果边界、类型与原子发布

验证 500 行边界、紧凑 UTF-8 编码恰好 1 MiB 与超出 1 字节、列定义过大、任意单行过大、多字节字符和累计前缀截断。成功状态与快照必须原子可见；`bigint`、`numeric`、日期和时间戳按冻结类型合同序列化。不能通过公开固定数据稳定构造的精确字节场景，必须运行候选真实 PostgreSQL 集成测试并由审查者核对其输入与断言。

## S6：保留期与幂等清理

通过候选提供的可控时钟或真实数据库集成接缝验证 `finished_at + 24h` 前可读、到期后 HTTP 410 `result_expired`。重复清理只删除过期结果内容，保留审计运行且不影响保留期内快照。

## S7：固定数据、安全与权限回归

运行固定数据校验、统一测试入口和 SQL 绕过探针；确认系统对象、目录解析 cast、写语句和越权对象在执行前被拒绝。使用真实 analytics 执行身份证明写入失败，并确认 API 身份不能执行用户 analytics SQL。错误响应和默认日志不得泄漏原始数据库错误、DSN、凭据或堆栈。

## S8：Compose 隔离与重启

同时启动 2 个不同候选或同候选的独立 Compose 项目，使用不同端口、网络和数据卷。两个实例分别通过就绪与完整查询主链，停止或销毁其中一个不影响另一个。重启 API、Worker 和完整项目后，已持久化运行与结果仍符合生命周期合同。

## 判定

每个场景只能记为 `passed`、`failed` 或 `unverified`。`passed` 需要新鲜运行证据；环境不支持稳定构造或观察时记为 `unverified`，不得改用实现推断补成通过。评审者仍按 `evaluation-and-scoring.md` 的子项档位计分，不把场景数量直接换算为分数。
