# 企业知识治理与可追溯智能问答平台

## 1. 定位

首个 baseline 计划建设一个企业内部文档知识库与 RAG 智能问答系统。产品重点不是简单的“上传文件后聊天”，而是企业知识从进入系统到被安全、可靠、可追溯地使用的完整生命周期。

本文件只记录 AgentShip 对该 baseline 方向的选择。详细可行性分析、需求分析、架构设计和产品源码应位于独立的 `baseline/enterprise-rag` 分支。

## 2. 计划覆盖的能力

- PDF、Markdown 和受控网页内容的导入与解析
- 异步分块、向量化、索引、状态跟踪和失败重试
- 基于检索增强的智能问答
- 回答引用定位到具体文档、版本和片段
- 缺少充分依据时明确拒答
- 组织、知识库和文档级权限隔离
- 问答历史、用户反馈、审计和成本观测

## 3. 工程关注点

- 权限过滤必须在检索阶段生效，不能只在生成回答后过滤。
- 处理流水线需要具备幂等性、重试和可观察状态。
- 文档更新、删除和重新索引后，引用关系应保持一致。
- LLM、Embedding 和 Rerank 应通过明确的 Provider 边界接入。
- 自动化验证不应完全依赖具有波动的在线模型响应。
- 网页导入测试应使用本地站点或固定快照，避免公网内容变化。

## 4. 首个任务方向

首个端到端任务暂定为“文档导入到可引用问答”的完整闭环：

1. 用户上传 PDF 或 Markdown。
2. 系统异步解析、分块、向量化并建立索引。
3. 有权限的用户可以提问并获得带引用的回答。
4. 处理失败可以重试，重复提交不能产生重复索引。
5. 无充分知识依据时必须明确拒答。
6. 管理员可以查看处理状态和问答反馈。

该任务仍需在 baseline 骨架完成后，根据实际项目边界形成正式版本和验收标准。
