# 评测范围与资料分工

## 1. 文档职责

本文只固定 AgentShip 的评测对象、共同输入和资料边界，不定义最终评分权重、隐藏验证实现或具体评审流程。评审方案由 WSL 侧单独确定并版本化。

## 2. 评测对象

AgentShip 评估完整的 AI 开发 Agent 系统，而不是脱离工具的裸模型。完整系统包括：

- 底层模型；
- Agent 外层工具及系统提示；
- 上下文发现、记忆和压缩机制；
- 文件、终端、浏览器和代码执行能力；
- 权限确认、失败恢复和交互方式。

目标是观察开发者实际使用某个“模型 + Agent 工具”系统时，能否完成真实软件开发，而不是比较抽象模型的单轮代码生成能力。

## 3. Windows 侧准备内容

Windows 侧 AgentShip 工作区先准备并通过 Git 提供：

- 项目介绍和背景；
- 产品需求、技术栈和固定数据契约；
- 可重复的公开合成数据集；
- 首轮业务范围和开发边界。

Windows 侧当前不负责确定正式提示词、协作记录、运行结果或评分方案。

## 4. WSL 侧工作内容

WSL 侧从本仓库拉取定稿内容，并负责：

- 真实 baseline 产品仓库的初始结构和项目内生文档治理；
- baseline 快照、独立工作树和运行环境；
- 各阶段开发委托和发送给 Agent 的提示词；
- Agent 自主提问、人工介入和过程协作记录；
- 运行结果、产物索引和后续比较资料；
- 最终评审方案、隐藏验证和评分实现；
- 将以上内容提交到同一个 AgentShip 远端仓库。

产品仓库不包含 AgentShip 的评测叙事、评分规则、隐藏测试、候选名单或其他模型的实现。

## 5. 共同外部条件

正式运行应尽量统一：

- 需求、数据集、开发委托和提示词版本；
- baseline commit 和运行时环境；
- Agent 可见的初始信息；
- 人工介入边界和记录方式。

不同 Agent 可以使用各自的原生工具、记忆和交互能力。评测的是完整系统，因此不强行抹平工具差异。

## 6. 过程与结果记录

每次运行至少保留：

- 使用的需求、数据和提示词版本；
- Agent 自主提出的问题及回答或决策过程；
- 起始 baseline commit、结果 commit 和工作树标识；
- 开始/结束时间、token 消耗、工具调用和人工介入；
- 运行命令、验证证据、失败信息和交付说明；
- WSL 侧按正式评审方案产生的结果和评审结论。

时间和 token 用于效率分析，但不预先截断正常开发过程。候选 Agent 持续工作到当前阶段目标完成或明确失败；异常长时间运行、环境故障和人工中止应单独记录。

## 7. 信息隔离

baseline 是独立的真实产品仓库，候选 Agent 不应看到其他 Agent 的分支、工作树、运行记录、评审规则或比较结果。worktree 不是严格的信息安全边界；若未来需要更强隔离，应使用独立 clone 或临时私有远端。

本仓库的公开内容应避免把具体项目做成可通过搜索直接复用的答案。数据集使用项目自有的确定性合成数据，不直接复制 Northwind、Chinook 等常见样例库。
