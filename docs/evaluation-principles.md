# 评测原则

## 1. 评测对象

AgentShip 评测完整的 AI 开发 Agent 系统，而不是脱离实际工具的裸模型。完整系统包括：

- 底层模型
- Agent 外层工具及其系统提示
- 上下文发现和压缩机制
- 文件、终端、浏览器等工具调用能力
- 权限确认、失败恢复和交互方式

目标是衡量开发者实际选择某个产品后能够获得的综合交付能力。

## 2. 公平条件

公平不等于强制所有 Agent 使用相同内部机制，而是统一外部任务条件：

- 相同的 baseline commit
- 相同的用户任务说明
- 相同的验收目标和禁止事项
- 相同的初始数据与依赖环境
- 明确的时间、费用和人工介入边界

每个 Agent 可以正常使用自身提供的原生能力。

## 3. 真实开发任务

评测任务应形成完整的业务闭环，要求 Agent 阅读项目、理解需求、修改多个工程层次、运行验证并交付结果。

任务不应退化为：

- 单独制作一个页面
- 增加一个孤立 CRUD 接口
- 按公开评分点机械填充文件
- 只依赖代码数量或测试数量刷分

## 4. 防止信息污染

- 使用此前未与候选 Agent 共同开发的项目主题和代码库。
- baseline 项目不包含评测规则、候选名单和其他结果。
- 正式运行使用从固定 commit 导出的干净仓库。
- 隐藏测试和评分实现保留在候选工作区外部。
- 记录候选 Agent 的记忆、网络和上下文设置。

无法完全消除模型的通用知识，但应避免精确项目、历史实现和既有对话记忆造成的直接泄漏。

## 5. 结果维度

未来评测至少考虑：

- 功能正确性和隐藏测试结果
- 回归、安全和数据一致性
- 工程设计与可维护性
- 调试、验证和失败恢复
- 时间、费用和工具调用
- 人工介入次数和操作者体感

单次运行不能代表稳定能力。同一任务应在条件允许时重复运行，并同时报告中位表现和波动。
