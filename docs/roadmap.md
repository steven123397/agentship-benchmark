# 路线图

## 阶段 0：主分支基础

- 建立 AgentShip 项目说明。
- 固化元仓库、产品仓库和 baseline 快照模型。
- 记录评测原则和首个项目方向。

## 阶段 1：Windows 侧准备

- 完成受治理 AI 数据分析平台的需求分析和技术栈选型。
- 固定五张分析表的数据契约、公开合成数据和可重复生成/校验流程。
- 完成项目说明、仓库模型和首轮业务边界。
- 提交稳定版本，供 WSL 侧通过 Git 拉取。

## 阶段 2：WSL 侧任务与产品设计

- 从 Windows 侧拉取已经定稿的需求、技术栈和数据集。
- 使用真实产品名称创建独立的本地和远端仓库。
- 确定 baseline 产品仓库的初始结构、项目治理规则和固定 baseline tag。
- 编写首轮提示词，确定协作记录、运行结果、正式评审方案和归档方式。

## 阶段 3：首次从零搭建任务

- 选择固定 baseline commit。
- 编写范围克制的第一条端到端任务。
- 要求候选 Agent 从零建立项目基座和最小纵向业务闭环。
- 定义公开验收标准、隐藏验证和人工评审维度。
- 固定提示词、运行限制和记录格式。

## 阶段 4：试运行

- 从固定 baseline tag 为不同 Agent 创建本地结果分支和 worktree。
- 测试期间不向共享产品远端推送其他 Agent 的结果。
- 使用少量候选 Agent 验证流程是否公平、可复现。
- 修正环境、任务和评分中的歧义。

## 阶段 5：DecisionHarbor v0.2.0

- 从已验证的 v0.1.0 同步基座发展持久化异步查询生命周期。
- 固定持久化异步生命周期、独立 Worker、取消/重试、失联恢复、结果快照和轮询 API 的外部合同，同时保留内部队列与协调机制的实现自由。
- 以双 Worker 竞态、重启恢复、v0.1 安全回归和结果保留边界作为主要评测能力。
- 完成主分支实现与冻结验证后创建 `baseline-v0.2.0`，再启动候选测试。

## 暂不实施

- 自动化批量调度平台
- 公共排行榜
- Web 结果展示站点
- 大规模模型与 Agent 接入
